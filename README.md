# OverlayKiller

OverlayKiller は、ページを読みにくくする要素を後から消すための Chrome 拡張です。
自動で常時ブロックするのではなく、必要なときに手動で 1 回だけ実行します。

## できること
- 画面全体を覆うオーバーレイの削除
- 背景スクロールを止めるロックの解除
- 記事の途中に差し込まれた広告候補の削除
- 本文にかぶさる固定広告の削除
- 左右レール広告や下から出てくる固定広告の削除
- `body` 外に追加された固定広告や Google 注釈広告の処理
- 広告化された本文リンクの文字を残した無効化と Undo 復元
- 直前の実行をまとめて戻す `Undo`
- 標準/強め/プレビューの実行モード
- Undo した対象を次回から保護しやすくするローカル学習
- 語彙ヒントの追加インポートと設定調整

## 特徴
- 手動実行専用
- 通信遮断ではなく DOM 後処理型
- 本文らしい要素は保護して誤爆を減らす
- 広告度だけでなく本文度・危険度を見て削除を抑制する
- しきい値やヒントを設定画面から調整できる

## インストール
1. Chrome で `chrome://extensions/` を開く
2. 右上の「デベロッパー モード」を ON にする
3. 「パッケージ化されていない拡張機能を読み込む」を押す
4. このフォルダを選ぶ

## 使い方
拡張を読み込んだら、任意のページで次のどちらかを使います。

- ツールバーの OverlayKiller アイコンをクリック
- 右クリックメニューから実行
  - `広告/オーバーレイを削除（標準）`
  - `広告/オーバーレイを強めに削除`
  - `削除候補を表示（プレビュー）`
  - `削除候補の表示を消す`
  - `Undo（直前の非表示を戻す）`
  - `OverlayKiller 設定`

## 実行モード
- `標準`: 誤爆を抑えるモードです。本文度や危険度が高い候補は消さずに見送ります。
- `強め`: 読書妨害を優先するモードです。標準では見送る一部候補も削除します。
- `プレビュー`: 削除せず、候補をページ上に枠表示します。赤は削除寄り、黄は強め向け、青は保護寄りです。

ツールバークリック時の既定モードは設定画面で変更できます。

## 削除の優先順位
OverlayKiller は次の順で候補を見ます。

1. 画面を覆うオーバーレイや背面ロック
2. 本文の流れを切る記事中広告
3. 本文に重なる固定広告
4. 左右レールや下端・右下のドッキング広告
5. 画面端の固定バナー

広告っぽい単語だけではなく、位置、サイズ、本文との重なり、閉じるボタン、配信ホストなどを組み合わせて判定します。

## 設定できる項目
主な設定は次のとおりです。

- 記事中広告の各シグナル ON/OFF
- 記事中広告のしきい値
- 1 回で消す上限件数
- 画面を覆う要素の削除 ON/OFF
- 画面端の固定バナー削除 ON/OFF
- 本文を覆う固定広告削除 ON/OFF
- 本文重なりの閾値
- 語彙ヒントのインポートと有効化

### 誤爆したとき
1. `Undo` で戻す
2. `Undoした対象を次回から保護しやすくする` が ON なら、戻した対象は同じサイトで保護されやすくなります
3. 固定広告や固定バナーの設定を弱める
4. 記事中広告のしきい値を上げる
5. 本文重なりの閾値を上げる

## 語彙ヒントの読み込み
設定画面から `.txt` または `.json` を読み込めます。

- `.txt`
  - hosts 形式や Adblock 系フィルタから語彙やホストを抽出
- `.json`
  - `{"words": [...]}` 形式の語彙セットを読み込み

語彙ヒントは補助材料です。強い広告配信ホストや UI 構造は別レイヤーでも判定します。

## 向いているケース
- モーダルや年齢確認風オーバーレイ
- 記事本文の途中にある差し込み広告
- 本文に重なる固定プレイヤー広告
- 左右のレール広告
- 下からせり上がる広告や右下固定広告

## 注意事項
- すべてのサイトで完全に動作することは保証していません
- サイトの HTML 構造が特殊な場合は取りこぼしがあります
- 通常の動画プレイヤーや本文コンテンツを守るため、保守的に判定する場面があります
- リンクは閉じるボタンとして自動クリックせず、オーバーレイ自体の非表示だけを行います
- 拡張更新後も開いたままのタブで受信に失敗した場合は、最新の `content.js` をそのタブへ再注入して一度だけ再実行します
- `webRequest` や `declarativeNetRequest` のような通信遮断型ではありません
- open な Shadow DOM は探索しますが、すべてのケースに対応しているわけではありません
